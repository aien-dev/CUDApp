# Native Blackwell components (CUDApp #157)

## Implementation and integration boundary

All production component generation, effects, interval construction, global linear-scan allocation and serialization are seeded Omega. The eight-cell unsolved instruction layout is the existing `BlackwellIRProgram` encoder bridge layout, not another IR. No solved instruction bytes are embedded in components.

Concatenate `bw_alloc.om`, `bw_effect.om`, `bw_check.om`, `bw_project.om`, `rowpipe.om`, `staged.om`, then `compose.om`. `bc_compose(cfg16, ins8192, metadata2048, phys288, out8) -> uint` generates the complete unsolved program, validates operands/bundles/branches/resources, then invokes one global allocation with the existing GPR limit. No component allocates physical registers. Effects are resolved over one continuous emission state, including load read barriers, held prefetch scoreboards, predicates and reconvergence. The existing relative branch patching and loop-lifetime extension are retained.

`cfg` words: family (1 direct, 2 rowpipe, 3 staged), K, lane bytes, rows/MT, warps, component selection (direct weight-first, staged rowmap, rowpipe zero), mutant zero, remaining words zero. Output words: instruction count, required GPR extent, required UGPR extent, required shared bytes, virtual GPR count, virtual UGPR count, zero, zero. A nonzero return must never be consumed as a realization.

`bc_project` and `bc_rowpipe` accept eight-word generator specs; `bc_staged` accepts sixteen words. Their outputs remain unsolved and use the same width/alias/lane namespace. Metadata stores widths at0, first/last intervals at288/576, allocation at864, active scratch at1152, stable order at1440. Direct folded-E4M3 decode preserves the existing multiply/shift/sign-bit method; the final byte uses a right shift, not a fabricated integer interpretation of a fractional scale. `bc_mma` checks the existing BF16 HMMA bundle contract and reader-spacing instructions; the migrated FP8 kernels deliberately retain their original FFMA arithmetic, not an unqualified tensor-core replacement.

After allocation concatenate the unchanged repaired function-mode encoder and semantic spec from [CUDApp revision1c5a8398d93b49e6765c2e3752aaad8611027d0d](https://github.com/aien-dev/CUDApp/commit/1c5a8398d93b49e6765c2e3752aaad8611027d0d), draft dependency [#168](https://github.com/aien-dev/CUDApp/pull/168), then `encode.om`. Each `bc_encode` invocation owns one zero-initialized3001-word spec workspace, reused for all instructions. It emits only words returned by checked `sp_enc`; padding is a semantic NOP encoded through that same checker, never pasted machine bytes or a second permissive emission. The standalone spec driver is no longer part of the unit. Direct/staged callers compare padded output; rowpipe compares the complete unpadded output.

Main's integration owner alone changes shared registration, generated bridges, public headers, runtime caller selection and cache/graph consumption. Export roots and types above are the integration patch contract; these files do not create another host emitter or silently select a C fallback. The C source is used only as an independent migration oracle here. QuantSchema dependency is fe25929ce71b11703eafa72395df2dd495aa61f2. The production compiler SHA256 remains2c82480596bbdc50cda9626866209ef662d5834f278f839ff4ce0250c495029f.

## Exercised host evidence

The permanent conductor is seeded Omega: `tests/components/proc.om`, `cases.om` and `run.om`. It handles process execution, exact I/O, source concatenation, case selection, refusals and receipt serialization; no Python or shell program implements those paths. Bootstrap and run it from the repository root using the pinned compiler and explicit verification-tool paths:

```sh
mkdir -p build/components
cat tests/components/proc.om tests/components/cases.om tests/components/run.om |
  "$OMEGA_OMC" > build/components/conductor
chmod +x build/components/conductor
build/components/conductor "$OMEGA_OMC" "$COMPONENT_ENCODER_DIR" \
  "$(command -v nvdisasm)" "$(command -v cc)" "$(command -v sha256sum)"
```

The conductor checks the compiler and repaired encoder/spec source pins and uses no GPU. `build/components/receipt.json` is complete only after all checks pass and the conductor exits0; any nonzero exit may leave a partial receipt and is not PASS. It exercises the actual composer root for direct, changed direct component, rowpipe, dense staged and mapped staged generation, plus refusal. Complete frame comparisons cover generation statistics, every virtual width, physical allocation, every existing IR cell and the entire encoded kernel. Independent nvdisasm decodes every emitted instruction. `tests/components/host-receipt.json` records eight direct, fourteen rowpipe and five staged cases, complete numerical transcripts and source/tool identities. Negative controls cover scoreboard read/held waits, branches, typed bundles, invalid op, register exhaustion, malformed frames and unsupported component fields. The pinned Omega MCP lookup, compile, run and explain_error tools were used for assistance; compilation alone is not behavior evidence.

Every native frame also runs through the existing `sim_gemv`/`parity` or `sim_point2` numerical seams. `numerical.c` replaces only the generator callback with deserialization of the actual Omega-produced instruction/allocation frame; it does not implement an interpreter, data generator, packing routine or reference arithmetic. Direct/rowpipe cover distinct experts and activation rows against the existing double oracle. Dense/mapped staged cover both fragment orders, multiple segments, an empty segment, tail rows and actual YMAP movement, bit-identical to the existing emulation. Every case additionally runs an FFMA-to-FADD wrong-result mutant which must execute successfully yet disagree numerically, and an unknown-op mutant which must retain the existing simulator refusal. The base simulator now permits an explicit `WS_MAX_THREADS` configuration, matching the existing `_k` simulator; its default and opcode semantics are unchanged.

`tests/components/wolfram.json` preserves Main's mounted Wolfram query/result for exact decode/control constants. In particular, the final byte's modeled scale is exactly1/16, and the migrated existing algorithm explicitly uses its source right-shift operation. The verifier tools were nvdisasm CUDA13.0 V13.0.85 and cc Ubuntu13.3.0-6ubuntu2~24.04.1. They are read-only qualification oracles, not production dependencies.

## Canonical tile and resource scope

Words14/15/16 are the **per-warp** logical output tile M, output tile N, and K-step. Direct/rowpipe use (1, rows, 32*lane_bytes); staged uses (MT,1,32*lane_bytes). This is source-grounded by `omega_blackwell_codegen_gemm.h`12 (one weight row per warp, MT accumulators) and32 (CTA spans warps weight rows). Word17 separately records the CTA warp count. No inferred alternative staged NI formula is authoritative.

Realization resources are actual declared launch resources, not merely generator minima: the current legacy QMD builder rounds GPRs and uses shared1024 when a zero request is supplied. A bound canonical record must describe the actual resulting declaration (including padding), independently dominate the emitted requirements and agree with the actual template. Never silently reinterpret a canonical shared0 as1024. UGPR is the required code/ABI extent, not permission to invent a configurable QMD field. `fixture.om` contains synthetic nonzero digest sentinels for schema tests only; it cannot establish artifact admission or hardware safety.

Launch sub-preimages use existing admitted artifact bytes, not a parallel metadata format:

- Parameter ABI: the unique target `.nv.info.<kernel_function>` section's exact contiguous prefix, from the leading attribute0x37 through all KPARAM_INFO0x17 records, parameter-size0x19 and the complete PARAM_CBANK0x0a record, stopping before resource attributes. Existing authority is `om/cubin/cubin_elf.om` (`wpar` and the first16 bytes of `wtail`) and `src/omega_cubin.c`. A strict parser must check ELF bounds/linkage, record order, formats, lengths, supported values and uniqueness. Attribute0x19 is format3: its following16-bit field is a value, not a payload length.
- Constant bank: exact `.cbank_args.bin` template bytes, whose length must equal four times launchword12.
- Zero-VA QMD: exact `.qmd0.bin` bytes followed immediately by exact `.qmd1.bin` bytes; each contains exactly96 existing32-bit words. Neither may contain live device addresses. Do not concatenate hexadecimal hashes or normalize addresses before hashing.

Compute hashes, cross-field checks and consumption from the same admitted snapshots, not separately reopened files. The ABI prefix is not an injective description of arbitrary exporter-supported scalar sizes: a nonfinal scalar size can change without changing the serialized prefix. The native subset therefore separately requires typed64-bit arguments and supported offsets/count/extent; hashes do not establish this restriction. Constant-bank32-bit word count is not parameter count. These are required integration admission conditions, not a claim that this lane exercised the shared loader.

Native/host implementation does NOT grant hardware qualification, service activation or GPU authority. Cache hashes exact1152 bytes, uses codeid/launchid accessors, and independently binds blobs. Selector admits each exact candidate qualification with effects/resources/costs; no inheritance across compose_match.
