# Native Blackwell components (CUDApp #157)

## Implementation and integration boundary

All production component generation, effects, interval construction, global linear-scan allocation and serialization are seeded Omega. The eight-cell unsolved instruction layout is the existing `BlackwellIRProgram` encoder bridge layout, not another IR. No solved instruction bytes are embedded in components.

Concatenate `bw_alloc.om`, `bw_effect.om`, `bw_check.om`, `bw_project.om`, `rowpipe.om`, `staged.om`, then `compose.om`. `bc_compose(cfg16, ins8192, metadata2048, phys288, out8) -> uint` generates the complete unsolved program, validates operands/bundles/branches/resources, then invokes one global allocation with the existing GPR limit. No component allocates physical registers. Effects are resolved over one continuous emission state, including load read barriers, held prefetch scoreboards, predicates and reconvergence. The existing relative branch patching and loop-lifetime extension are retained.

`cfg` words: family (1 direct, 2 rowpipe, 3 staged), K, lane bytes, rows/MT, warps, component selection (direct weight-first, staged rowmap, rowpipe zero), mutant zero, remaining words zero. Output words: instruction count, required GPR extent, required UGPR extent, required shared bytes, virtual GPR count, virtual UGPR count, zero, zero. A nonzero return must never be consumed as a realization.

`bc_project` and `bc_rowpipe` accept eight-word generator specs; `bc_staged` accepts sixteen words. Their outputs remain unsolved and use the same width/alias/lane namespace. Metadata stores widths at0, first/last intervals at288/576, allocation at864, active scratch at1152, stable order at1440. Direct folded-E4M3 decode preserves the existing multiply/shift/sign-bit method; the final byte uses a right shift, not a fabricated integer interpretation of a fractional scale. `bc_mma` checks the existing BF16 HMMA bundle contract and reader-spacing instructions; the migrated FP8 kernels deliberately retain their original FFMA arithmetic, not an unqualified tensor-core replacement.

After allocation concatenate the unchanged repaired encoder and semantic spec from CUDApp revision85c059cc15edf704c9833fe4832f18c052ee83b3, omitting only the spec file's standalone `fn main` driver, then `encode.om`. `bc_encode` checks each authored operand with `sp_enc` before calling the unchanged `bw_enc_sm121`. Direct/staged callers compare padded output; rowpipe compares the complete unpadded output.

Main's integration owner alone changes shared registration, generated bridges, public headers, runtime caller selection and cache/graph consumption. Export roots and types above are the integration patch contract; these files do not create another host emitter or silently select a C fallback. ## Canonical tile and resource scope

Words14/15/16 are the **per-warp** logical output tile M, output tile N, and K-step. Direct/rowpipe use (1, rows, 32*lane_bytes); staged uses (MT,1,32*lane_bytes). This is source-grounded by `omega_blackwell_codegen_gemm.h`12 (one weight row per warp, MT accumulators) and32 (CTA spans warps weight rows). Word17 separately records the CTA warp count. No inferred alternative staged NI formula is authoritative.

Realization resources are actual declared launch resources, not merely generator minima: the current legacy QMD builder rounds GPRs and uses shared1024 when a zero request is supplied. A bound canonical record must describe the actual resulting declaration (including padding), independently dominate the emitted requirements and agree with the actual template. Never silently reinterpret a canonical shared0 as1024. UGPR is the required code/ABI extent, not permission to invent a configurable QMD field. `fixture.om` contains synthetic nonzero digest sentinels for schema tests only; it cannot establish artifact admission or hardware safety.
