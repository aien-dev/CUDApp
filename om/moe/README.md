## Native plan contract

`moe_plan` is pure. Six disjoint ABI1 arrays: cfg ulong[8], ids ulong[1024], work ulong[10368], segments ulong[1028], maps ulong[2320], meta ulong[8]. The production bridge accepts ulong/uchar, not uint arrays. These logical ulong words are deliberately NOT the GPU representation. Explicit Omega serializers below produce existing u32 maps and Seg32 bytes, without a new format or host algorithm.

Cfg: version1, tokens0..128, route slots0..8, routed expert count1..256, shared id exactly expert count, work capacity in records, segment capacity in records, map capacity per map including eight padding entries. Maximum backing capacities:1152,257,1160. Input IDs are token-major original slots, either below routed expert count or UINT32_MAX (absent). Every other ID refuses, never `id & 255` as in historical pf_group. All bounds and IDs are validated before any output write.

Each work record has nine fields: expert id, source activation row, token id, original route slot, token-local weight slot, containing segment offset, containing segment count, original dense contribution destination, original contribution order. Stable order is expert then token then original slot. Shared expert is explicit, one contribution per token, with slot/weight/order equal to routed slot count. Shared is the final segment, never merged into routed expert255. Segments contain expert, global work offset, count, shared flag. They have no addresses and must not be cast to Seg32.

Gate/up uses X/Y maps; down uses Y/Y. X starts at0; Y starts at1160. Eight zero entries follow active rows of each map. Other unused outputs remain unchanged. Meta: work count, segment count, routed count, shared count, version1, three zero reserved words. Return0 success;1 invalid cfg;2 invalid ID;3 capacity. Refusals preserve all outputs. Zero tokens and shared-only work are supported.

No-pick plans retain holes and original route slots. They are NOT directly admissible to unchanged dense q36 combine: a consumer must clear omitted destinations or combine only present contributions in original order. The resident candidate admits only the incumbent complete router outputs, not this general sparse extension.

`moe_ids32` decodes active existing little-endian router u32 picks into logical ABI words, without masking. `moe_maps32` validates every active value then writes existing little-endian u32 map bytes, including padding, preserving unused output bytes. `moe_segs32` validates ranges and live aligned directory entries then writes exact existing32-byte Seg32 records: weight VA, scale VA, row0 u32, count u32, reserved zero u64. Its directory is the incumbent257 pairs(weight,scale), shared index256; call once for gate/up and once for down. Quantization descriptors remain the canonical QuantSchema contract, not another MoE serializer.

## Resident scheduling candidate

`moe_group` emits exactly64 bytes / OMEGA_DEC_GR_WORDS16 for existing K_GROUP groups9. Request16 words: ids VA, GU table VA, down table VA, GU segment VA, down segment VA, X map VA, Y map VA, router stride, window tokens, segment capacity, per-map capacity, directory slots9, session generation, current generation, admitted flag, shared id256. All seven addresses are nonzero/eight-byte aligned; stride is u32/16-byte aligned and covers a nine-entry table row. Checked address extents cannot wrap. Every written range is disjoint from all readers and other writers; read-only router fields may share their strided allocation. Return1 shape,2 capacity/stride extent,3 alignment/address,4 generation/admission,5 alias/extent overflow; output unchanged on refusal. Matching generation0 is valid, as in the canonical Cache/Selector. This low-level helper does not authenticate qualification or device residency. Trusted graph state checks allocation bounds and same-expert directory coherence under its existing session lock.

GROUP writes trailing descriptors through R-1 even when only one expert occurs: segment capacity must cover R, not distinct experts. GROUP's current one-CTA row bound is128; there is no inter-CTA spinning or new executor.

`moe_windows` covers the entire existing prefill token range0..128 with stable token windows satisfying `window_tokens*9 <= 128`. Input8: version1,total tokens,H2048,EI512,contributions9,router stride,window-record capacity<=128,flush_each(only0). Output backing ulong[1024], eight fields/window: token0,tokens,rows,XP byte offset,GU byte offset,ACT byte offset,DN byte offset,router byte offset. Meta4: windows,total tokens,total rows,version1. It validates capacities before publication. Thus large prefill does not require an unqualified multi-CTA GROUP. Each window records existing GROUP -> permutation -> indexed GU(X/Y) -> SwiGLU -> permutation -> indexed down(Y/Y), with addresses shifted to its original contribution slots. Existing command-list barriers complete down before the next window overwrites shared maps/descriptors. Original ordered combine runs after all windows. There is no host picks readback/sync between router and experts. No cross-window reassociation occurs.

`moe_admit` consumes exact canonical PipelineSelect q64/a1024 and KernelCache pool528; it calls the actual `pl_pin`, requires staged/indexed family3 and releases its recorded pin on wrong-family refusal. It does not define identity, quantization or qualification schemas. Existing session lock spans admission/recording. Existing cache acquire, observed-completion retire and recorded-list unpin are authoritative. Failure without proven completion must not fabricate a retire.

`q36-prefill-integration.patch` supplies the shared-file owner with router output projection, R+padding map allocation and actual window/combine record adapters calling its `native_record_gemm`.
